# 백엔드 요청: 참가자 카메라(WebRTC) 시그널 중계

작성 2026-08-19 · 요청자 프론트엔드 · 대상 서버 AWS (`VITE_API_BASE_URL` = `.env` 참고)

## 배경

세션 방의 참가자 타일이 회색인 이유는 영상 경로가 없었기 때문입니다. 웹캠은 손 제스처 인식용으로만
열려 있었고 다른 참가자에게 나가지 않았습니다.

프론트엔드는 참가자끼리 영상을 직접 주고받도록(WebRTC P2P) 구현을 마쳤습니다. **영상은 서버를
거치지 않습니다.** 미디어 서버·SFU 가 필요 없고 도면 동기화용 WS 대역폭도 쓰지 않습니다. 다만 P2P
연결을 맺으려면 두 참가자가 연결 정보(SDP·ICE)를 주고받아야 하고, 그 통로가 없습니다. 서버가 할 일은
그 메시지를 상대에게 그대로 전달하는 것 하나입니다.

요청은 두 가지입니다. 프론트엔드는 (2)가 `true` 일 때만 (1)을 보내므로, 배포 순서에 상관없이
지금 서버가 끊길 일은 없습니다. **서버가 켜 주기 전까지 참가자 영상은 꺼진 상태로 동작합니다.**

---

## 1. `signal` frame 1:1 중계

### Client → Server

```json
{ "t": "signal", "to": "<participantId>", "data": { "kind": "offer", "sdp": "v=0\r\n..." } }
```

### Server → Client (`to` 참가자에게만)

```json
{ "t": "signal", "from": "<보낸 참가자 id>", "data": { ...받은 data 그대로... } }
```

- `data` 는 **불투명(opaque)**. 파싱·검증·변형 없이 그대로 전달하면 됩니다. 내용 규격은 브라우저가
  정하고 프론트엔드끼리만 해석합니다. (`data.kind` 는 `offer`/`answer`/`ice`/`bye`)
- `from` 은 **서버가 채워 주세요.** 클라이언트 값을 믿으면 다른 참가자를 사칭할 수 있습니다.
  클라이언트는 `from` 을 보내지 않습니다.

### 처리 규칙

| 항목 | 요청 내용 |
| --- | --- |
| 대상 | `to` 로 지정된 **한 명에게만**. 브로드캐스트 금지 |
| 대상 범위 | 같은 방 · 현재 WS 에 붙어 있는(`active`) 참가자만. 아니면 조용히 버리기 |
| 없는 대상 / 자기 자신 | 연결을 끊지 말고 무시 |
| 순서 | 받은 순서 유지. 병합·재정렬 금지 (ICE candidate 는 순서가 의미를 가집니다) |
| 상태 | 저장·큐잉·재전송 없음. 대상이 없으면 버리기 |
| 크기 | SDP 는 3~8KB. **frame 하나당 최소 16KB** 통과 |
| 빈도 | 협상 1회에 20~40 frame(ICE 다발)이 몰립니다. **참가자당 초당 50 frame** 허용, 기존 `maxStateHz` 와 **별도 카운터**로 세 주세요 (같이 세면 협상 중 도면 전송이 막힙니다) |
| 로깅 | `data` 본문은 남기지 말아 주세요 (사설 IP·네트워크 구조가 찍힙니다). 개수·크기만 |
| telemetry | `signal` 은 e2e 지연 표본에서 제외 (도면 동기화 지연 수치가 오염됩니다) |

## 2. `welcome.config.signalRelay`

```json
{ "t": "welcome", "config": { "signalRelay": true, "heartbeatMs": 2000, "...": "..." } }
```

중계를 배포한 뒤 `true` 로 내려 주세요. 필드가 없으면 프론트엔드는 `false`(참가자 영상 끔)로 봅니다.

---

## 서버가 하지 않아도 되는 것

미디어 처리(인코딩·디코딩·SFU), SDP/ICE 파싱·검증, 저장·재전송 — 모두 불필요합니다.

## 프론트엔드가 이미 처리한 것

- 협상 충돌(양쪽 동시 offer): W3C perfect negotiation. 참가자 id 가 큰 쪽이 양보합니다.
- 누가 먼저 offer 를 낼지: id 가 작은 쪽. 서버가 순서를 정할 필요 없습니다.
- 카메라 on/off: 열린 연결에 트랙만 교체하고 `presence.vid` 로 UI 를 바꿉니다.
- 퇴장: `bye` 전송 후 연결 종료. 못 보내도 `presenceLeave` 로 정리됩니다.

## 확인 부탁드릴 점

**모르는 `t` 값을 받으면 지금 서버는 어떻게 동작하나요?** 무시인지, 잘못된 frame 으로 세서 1008 로
끊는지에 따라 `signalRelay` 를 켜기 전에 프론트에서 미리 시험해 볼 수 있는지가 갈립니다.

## 지금은 요청하지 않는 것

- **TURN 서버(coturn).** 참가자들이 공용망에 있으면 대개 STUN 만으로 붙습니다. 프론트엔드 기본값은
  공용 STUN 이고 주소는 `VITE_ICE_SERVERS` 로 바꿀 수 있습니다. 실제로 붙지 않는 회선이 나오면
  그때 AWS 인스턴스에 coturn 을 요청하겠습니다.
- **음성.** 지금 구현은 영상만입니다. 마이크를 켜더라도 같은 `signal` 경로를 쓰므로 이 문서의 요청
  사항은 늘지 않습니다.
